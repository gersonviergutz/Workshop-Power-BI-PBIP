# Skill: Client Presentation para Projetos BI

## Quando usar
Use para criar material de validação com cliente, proposta de dashboard, apresentação de requisitos, escopo funcional ou mockups.

## Objetivo
Traduzir requisitos técnicos e dores de negócio em uma apresentação clara, executiva e aprovável.

## Estrutura recomendada
1. Contexto do projeto.
2. Dores identificadas.
3. Objetivos do dashboard.
4. Perguntas de negócio.
5. Indicadores propostos.
6. Páginas sugeridas.
7. Mockup conceitual.
8. Fontes de dados necessárias.
9. Critérios de aceite.
10. Próximos passos.

## Linguagem
- Executiva.
- Clara.
- Orientada a valor.
- Sem excesso técnico.
- Traduzir termos como TMDL/PBIR apenas se o público for técnico.

## Padrão para KPI na apresentação

```md
### KPI: Receita Líquida

**Pergunta que responde:** quanto a empresa vendeu após descontos/devoluções?

**Valor para gestão:** permite acompanhar crescimento, sazonalidade e desvios de performance.

**Visual sugerido:** card + linha mensal.
```

## Padrão para página de dashboard

```md
## Página: Visão Executiva

**Objetivo:** apresentar a saúde geral do negócio.

**Usuário principal:** diretoria/comercial.

**Indicadores:** receita, margem, pedidos, ticket médio, atingimento de meta.

**Decisões apoiadas:** priorizar ações comerciais e identificar desvios rapidamente.
```

## Checklist de aprovação
- O cliente entende o que será entregue?
- Os KPIs estão claros?
- Existem pendências explícitas?
- As páginas propostas refletem as dores?
- O escopo está protegido contra interpretações abertas?
